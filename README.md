# sshtool

一个用 Go 写的 **SSH 多会话终端 TUI**：左侧管理连接/收藏/历史，右侧是真实 PTY 终端，顶部标签栏在多台服务器之间切换。鼠标可点，快捷键可盲操。

```
┌────────────────────────────────────────────────────────────────────────────┐
│ ●1 web-01 ×  ●2 db-01 ×   ＋ 新连接      Alt+数字切换 · Ctrl+N新建 · …     │  ← 已连接服务器标签栏
├────────────────┬───────────────────────────────────────────────────────────┤
│ ① 保存的连接    │                                                           │
│   ● web-01     │   root@web-01:~# df -h                                     │
│   ● db-01      │   Filesystem      Size  Used Avail Use% Mounted on          │
│   ○ test-02    │   /dev/sda1        40G   12G   26G  32% /                   │
├────────────────┤                                                           │
│ ② 收藏命令      │   root@web-01:~# █                                         │
│   磁盘  df -h   │                                                           │
│   日志  tail -f │                                                           │
├────────────────┤                                                           │
│ ③ 历史命令      │                                                           │
│   systemctl …  │                                                           │
│   docker ps    │                                                           │
└────────────────┴───────────────────────────────────────────────────────────┘
 Tab 切换焦点 · Enter 执行 · / 过滤 · Ctrl+X 命令行 · Ctrl+W 关闭 · PgUp 回滚
```

## 特性

- **2:8 双列布局**，左列三块面板（保存的连接 / 收藏命令 / 历史命令）
- **多会话并行存活**：切换标签只是切换渲染目标，后台会话继续接收输出
- **真实 PTY**：`xterm-256color`，支持 `top` / `vim` 这类全屏程序、ANSI 256 色与 TrueColor、滚动回溯
- **两种输入模式**：直通模式（按键直达远端，远端回显）+ 命令行模式（本地编辑，回车整行发送并记录历史）
- **鼠标全可点**：标签切换 / 关闭、列表项选中、双击执行、滚轮滚动、对话框字段与按钮
- **配置持久化**：连接、收藏、历史落盘到 `~/.sshtool/config.json`（原子写 + `.bak` 备份）
- **SSH 密钥管理**（`Ctrl+G`）：本机生成密钥（可选算法 / 注释 / 保存路径 / 私钥口令），
  以及把现有公钥一键推到远端 `authorized_keys`（自定义端口、用户名、目标路径，自动修权限、幂等去重、
  支持一次分发到多台主机）
- **底部状态栏实时显示远端当前路径**：连接建立后由远端 shell 通过 OSC 标题静默上报工作目录，
  无需轮询命令、不污染屏幕；`cd` 切换目录后状态栏自动刷新
- **远端文件浏览器**（`Ctrl+O`）：基于 SFTP 浏览服务器文件系统，支持进入/返回目录、过滤；
  选中文件后调用**本地默认程序**打开，编辑保存后改动**自动回传**远端（适合快速改配置、看日志）；
  并支持双向传输与维护：`r` 重命名、`m` 改权限（八进制）、`n` 新建目录、`d` 下载到本地、
  `U` 上传本地文件、`D` 删除（目录递归、二次确认）
- **会话日志落盘与回放**：设置 `SSHTOOL_LOG_DIR` 后，每个会话的终端输出（含远端回显）实时写入磁盘，
  按 `Ctrl+L` 可在全屏「回放」视图里重看整段会话（↑↓/PgUp/PgDn 滚动），便于审计与复盘；状态栏显示「●记录」指示
- **心跳保活 + 断线自动重连**：每 30 秒发送 OpenSSH 保活探测，传输层断开（网络抖动 / 服务端重启）后
  自动按指数退避重连（默认最多 5 次，复用内存中的密码 / 私钥口令免重复询问），状态栏显示「重连中 / 已恢复连接」；
  用户主动退出 shell（`exit`）或关闭会话不触发重连。可用环境变量 `SSHTOOL_KEEPALIVE_SECS`、`SSHTOOL_RECONNECT_MAX`、
  `SSHTOOL_RECONNECT_BASE` 调参（`SSHTOOL_KEEPALIVE_SECS=0` 关闭保活）
- **主题切换**：内置 `dark`（默认，tokyo-night 风格）与 `light` 两套配色，由配置文件 `theme` 字段控制
  （修改后重启生效），也可在命令行模式输入 `theme light` / `theme dark` 实时切换并持久化

## 构建与运行

需要 Go 1.21+（本项目在 Go 1.26 上开发）。

```bash
git clone https://github.com/jackguoguoguo/go_ssh.git
cd go_ssh

# 方式一：一键打包（推荐）
powershell -ExecutionPolicy Bypass -File .\build.ps1 -Version v0.1.0   # Windows
make build VERSION=v0.1.0                                              # Linux / macOS

# 方式二：直接 go build
go build -o sshtool .     # Windows: go build -o sshtool.exe .
./sshtool

# 方式三：不打包直接跑
go run .
```

打包脚本参数：

| 命令 | 说明 |
|---|---|
| `.\build.ps1` | 构建当前平台 → `dist/sshtool.exe` |
| `.\build.ps1 -All` | 交叉构建 `windows-amd64` / `linux-amd64` / `darwin-arm64` |
| `.\build.ps1 -Version v1.2.3` | 注入版本号（`sshtool -v` 可查） |
| `.\build.ps1 -Run` | 构建完成后立即启动 |
| `make build-all` | 等价的 Makefile 交叉构建目标 |

产物采用 `-trimpath -ldflags "-s -w"` 构建，体积约 6 MB。

其他命令：

```bash
go test ./...     # 运行测试（含进程内 SSH 服务端的端到端测试）
go vet ./...      # 静态检查
gofmt -w .        # 格式化
sshtool -v        # 查看版本与配置文件路径
```

> 建议在支持 256 色的终端中运行（Windows Terminal / iTerm2 / GNOME Terminal 等）。

## 配置

配置文件默认位于 `~/.sshtool/config.json`（Windows：`%USERPROFILE%\.sshtool\config.json`），首次运行自动生成。

```jsonc
{
  "connections": [{
    "id": "…", "name": "web-01", "group": "生产",
    "host": "10.0.0.1", "port": 22, "user": "root",
    "auth_type": "password",       // password | key
    "password": "",                // 留空则连接时询问
    "ask_password": true,          // 每次连接都问密码（推荐，避免明文落盘）
    "key_path": "~/.ssh/id_rsa",   // auth_type=key 时生效
    "key_passphrase": "", "ask_passphrase": false,
    "startup_cmd": "", "note": "", "favorite": false
  }],
  "favorites":  [{ "id": "…", "name": "磁盘", "cmd": "df -h", "group": "" }],
  "history":    [{ "id": "…", "cmd": "docker ps", "host": "10.0.0.1", "at": "…" }],
  "settings":   { "history_limit": 1000, "scrollback": 5000, "theme": "dark" }
}
```

主机指纹校验严格使用 `~/.ssh/known_hosts`：首次连接陌生主机会弹出指纹确认，确认后写入 `known_hosts`；
若指纹与 `known_hosts` 已有记录不符（疑似中间人攻击或主机重装），**直接拒绝连接**。
设置环境变量 `SSHTOOL_INSECURE_HOST_KEYS=1` 可退回不校验（仅供批量脚本）。

### 心跳与重连调参

| 环境变量 | 默认值 | 作用 |
|---|---|---|
| `SSHTOOL_KEEPALIVE_SECS` | `30` | 保活探测间隔（秒）；设为 `0` 关闭保活，仅依赖传输层错误触发重连 |
| `SSHTOOL_RECONNECT_MAX` | `5` | 自动重连最大尝试次数，耗尽后置异常态并提示 `Ctrl+R` 手动重连 |
| `SSHTOOL_RECONNECT_BASE` | `2` | 重连退避基数（秒），第 N 次重试等待 `base × 2^(N-2)` 秒，封顶 30 秒 |
| `SSHTOOL_LOG_DIR` | 空（不记录） | 会话日志目录；非空时每个会话的终端输出落盘到 `<dir>/<user@host_port>/<id>_<时间>.log`，供 `Ctrl+L` 回放 |

## SSH 密钥管理（`Ctrl+G`）

### 1. 本机生成密钥

菜单「① 生成新密钥」→ 填 4 个字段 → 生成：

| 字段 | 说明 |
|---|---|
| 算法 | `ed25519`（推荐）/ `ecdsa-256` / `rsa-4096` / `rsa-2048`，`←` `→` 切换 |
| 注释 | 默认 `user@host`，建议写成用途（如 `deploy@CI`、`laptop-2026`） |
| 私钥路径 | 默认 `~/.ssh/id_<算法>`，可任意指定；公钥自动落在同名 `.pub` |
| 私钥口令 | 可留空；填写后私钥以 OpenSSH 新格式加密存储 |

生成 RSA 会明显更慢（4096 位通常几秒），因此放在后台协程执行，界面显示「正在生成…」而不会卡住。
生成完成后会展示私钥/公钥路径、算法、指纹，以及**可直接整行复制的公钥内容**。

已存在同名文件时会拒绝覆盖（提示换路径或勾选覆盖），私钥权限强制 `0600`、公钥 `0644`。

### 2. 推送公钥到远端 `authorized_keys`

菜单「② 推送公钥到服务器」→ 选本机公钥（或手动输入路径）→ **多选目标服务器**（空格勾选、`a` 全选、
输入关键字过滤）→ 确认远端路径（默认 `~/.ssh/authorized_keys`）→ 并发执行。

远端只跑一段幂等 shell（单条 `exec`，不需要 scp/sftp，也不申请 PTY）：

```sh
P="$HOME/.ssh/authorized_keys"      # 支持自定义路径：~ 开头会转成 $HOME
mkdir -p "$(dirname "$P")"; chmod 700 "$(dirname "$P")"
touch "$P"; chmod 600 "$P"
K='ssh-ed25519 AAAA... 注释'
set -- $K; B="$1 $2"                # 取「算法+密钥体」，忽略注释
grep -qF -- "$B" "$P" || printf '%s\n' "$K" >> "$P"   # 已存在则跳过
chmod 600 "$P"; chown "$(id -un)" "$P" "$(dirname "$P")"
```

行为要点：
- **自动处理权限**：`.ssh` 目录 `700`、`authorized_keys` `600`，并尝试 `chown` 给登录用户
- **幂等去重**：按「算法 + 密钥体」比较，**换注释重复推送不会写入第二行**
- **末尾无换行时自动补 `\n`** 再追加，避免把新密钥粘到上一行末尾
- **端口 / 用户名 / 目标路径**都取自连接配置或表单，可自定义
- 结果页按主机列出「已写入 / 已存在 / 失败（含原因）」以及当前条目数

### 3. 批量分发多台服务器

在目标选择界面多选即可，**并发**推送（每台独立超时 30s）。
同一台主机若在列表里出现多次（多个别名连接），会按 `user@host:port` **去重后只推一次**——
否则并发写同一个文件会出现重复行，这是实测复现过的竞态。

## 我推荐你继续补上的三件事

下面三项里，只有「批量分发」已经实现；另外两项给出的是推荐设计，需要的话我可以直接落地。

### ① 密钥的备份与恢复（推荐实现）

危险点：误删 `~/.ssh` 或重装系统后，若只靠密钥登录会**彻底失去服务器访问权**。

推荐做法（约 100 行）：

- **备份**：`Ctrl+G` 增加「备份密钥」——把 `~/.ssh` 下的 `id_*`（私钥 + `.pub`）+ `config` + `known_hosts`
  打包进 `~/.sshtool/backups/ssh-keys-YYYYmmdd-HHMMSS.tar.gz`，同时写一份 `manifest.json`
  （每个密钥的算法、指纹、注释、对应的连接 ID）。
  - 备份文件整体用**口令派生的对称密钥**加密（`scrypt` + `AES-GCM`，Go 标准库即可），
    否则把一个未加密的私钥压缩包放在磁盘上是明显的安全回退
  - 只备份 `id_*`，**不要**把 `known_hosts` 之外的东西混进来
- **恢复**：列出备份 → 校验指纹 → 选择覆盖或改名导入，并提示「恢复后请确认 `authorized_keys` 仍包含对应公钥」
- **快照式保险**：每次推送公钥前，自动把远端 `authorized_keys` 回传一份存到备份目录，
  这样误删远端授权也能一键回滚

### ② 基于标签的密钥分类查询（推荐实现）

目前只有「注释」一个维度，多台服务器 / 多用途时会很快失控。推荐在密钥元数据上加一层：

- 标签写在公钥注释里，用 `#` 分隔，例如 `deploy@CI #prod #ci #readonly`
- `~/.sshtool/keys.json` 维护 `{fingerprint, path, tags[], created_at, notes}` 索引，
  与注释双向同步（改注释即改标签）
- `Ctrl+G` 的选择器支持 `#prod` 这样的标签过滤，以及 `prod +ci`（与）、`prod,staging`（或）组合查询
- 顺带把连接也打上标签，就能做「把带 `#prod` 的密钥推给所有打 `prod` 标签的主机」这种批量操作

### ③ 其它值得做的（优先级从高到低）

- **ssh-agent 集成**：现在私钥口令每次都要手输；接上 agent 后可一次解锁全程复用
- **远端公钥盘点**：连上主机后拉取 `authorized_keys`，与本机密钥指纹比对，
  一眼看出「哪台还没授权」「哪台有已废弃的旧密钥」——这是最实用的一项审计能力
- **known_hosts 管理**：✔ 已实现——首次连接交互式确认指纹并落盘，指纹不符直接拒绝；见上「安全」一节
- **密钥轮换**：生成新密钥 → 批量分发 → 验证可登录 → 再从远端移除旧指纹，全流程自动化

## 已知限制（密钥相关）

- 备份 / 恢复、标签索引尚未实现（见上一节）
- 私钥口令不会缓存，批量推送时统一问一次口令，各主机需使用同一套凭据
- Windows 上 Go 无法设置 POSIX 权限位，私钥权限实际依赖目录 ACL（Unix 上为 `0600`）
- 并发推送同一台主机已按端点去重；若两条连接分别用不同用户名指向同一主机，仍会各自写一次（符合预期）

## 远端文件浏览器（`Ctrl+O`）

基于 SFTP subsystem，用图形化的方式浏览、打开、编辑服务器上的文件。

### 打开与使用

1. 先连接到一台服务器（`Ctrl+N` 建连接、回车连接）
2. 按 `Ctrl+O` 打开文件浏览器，默认进入远端当前工作目录（即状态栏显示的路径）
3. 导航：
   - `↑` `↓` / `PgUp` `PgDn` 移动；`Enter` 进入目录 或 打开文件
   - `u` 或 `Backspace` 返回上一级；`~` 回到家目录
   - `/` 或直接输入字符过滤文件名（再按 `Esc` 先清空过滤、再按 `Esc` 关闭）
4. 打开文件：
   - **`Enter`**：把文件下载到本地临时目录（`%TEMP%/sshtool-*`），用系统**默认程序**打开
   - **`e`**：编辑模式——同样下载并打开，但会启动一个监听协程，**本地保存后自动回传**到远端原路径（适合改 `nginx.conf`、看 `app.log` 等）
5. 双向传输与维护（对话框底部有提示，操作结果在状态栏反馈）：
   - **`r`** 重命名：输入新名称并回车（默认填入当前名）
   - **`m`** 改权限：输入八进制权限（如 `644`、`0755`）并回车
   - **`n`** 新建目录：输入目录名并回车（相对当前目录）
   - **`d`** 下载到本地：输入本地路径并回车（默认填文件名，相对本地当前工作目录）
   - **`U`** 上传本地文件：输入本地文件路径并回车，上传到当前远端目录（同名覆盖）
   - **`D`** 删除：目录则**递归删除**，需在提示行按 `y`/`Enter` 二次确认，其它键取消

### 实现要点

- 远端路径通过 SFTP 直接读写，不依赖 `scp`/`sftp` 命令行，也不申请 PTY
- 远端当前目录的「静默同步」：连接建立后向 shell 注入
  `PROMPT_COMMAND='printf "\033]0;SSHTPWD:%s\033\\" "$(pwd)"'`（bash 支持；sh 仅设了一个无害的环境变量），
  shell 每次刷新提示符时会把 `SSHTPWD:<cwd>` 写进 OSC 标题；终端模拟器 `internal/vt` 捕获标题但**不渲染到屏幕**，
  UI 直接读 `Terminal.Title()` 即可拿到远端 cwd，状态栏由此实时刷新，`cd` 后立刻更新
- 本地打开走系统关联程序：Windows 用 `cmd /c start`、macOS 用 `open`、Linux 用 `xdg-open`
- 自动回传采用 700ms 轮询本地临时文件 mtime，发生改动则回写远端；关闭对话框会停止监听并释放 SFTP 通道

### 已知限制

- 本地「用默认程序打开」在 Windows 上依赖 `cmd /c start`；若远端是 Linux 服务器、本地是 Windows，
  编辑用到的是**本地**的记事本 / VS Code 等，不是远端编辑器（这是「本地工具编辑远端文件」的预期模式）
- `PROMPT_COMMAND` 仅在 bash 等兼容 shell 生效；若远端用的是 `sh`/`dash` 且未手动设置，状态栏会显示「未知目录」，
  此时可通过命令行 `cd` 后由 UI 的本地解析兜底

## 代码结构

```
main.go                  入口
internal/store/          数据模型 + JSON 持久化（原子写、历史裁剪、并发安全）
internal/vt/             ANSI 终端模拟器：CSI/OSC 解析、256 色、宽字符、滚动区、scrollback
internal/remotessh/      会话生命周期：认证、PTY、window-change、输出批量聚合、事件通知
internal/ui/             bubbletea 界面：布局、焦点状态机、快捷键、鼠标、对话框
internal/testutil/       测试用进程内 SSH 服务端
```

数据流：

```
远端 PTY ──▶ remotessh.Session 读协程（8ms 批量聚合）──▶ vt.Terminal 屏幕缓冲 ──▶ UI 渲染
UI 按键 ───▶ remotessh.Session.Write ────────────────────────────────▶ 远端 stdin
```

## 已知限制

- 复制走 OSC 52 写入系统剪贴板；极少数终端（或未开启「Allow OSC 52」的 tmux/终端模拟器）不支持时，内容会落到 `~/.sshtool/clipboard.txt` 作为兜底
- 支持 SFTP（`Ctrl+O` 文件浏览器）；尚未支持端口转发与 ProxyJump 跳板机（数据结构已预留 `group` 等字段，跳板机未实现）
- 终端模拟实现的是常用 CSI 子集（见 `internal/vt`），极少数冷门序列会被安全忽略
- 直通模式下不记录历史命令（避免把程序交互输出误当成命令），历史只在命令行模式发送时记录
